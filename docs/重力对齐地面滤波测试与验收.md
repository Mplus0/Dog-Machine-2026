# 重力对齐地面滤波：测试与验收

## 目标与安全边界

新节点使用 IMU 姿态把深度点云对齐到重力方向，再估计地面平面，只将高于地面的障碍物投影为二维扫描。默认配置同时保留原始 `/scan`，并把新结果发布到 `/scan_ground_filtered`，不会自动切换 AMCL 或代价地图。

在完成第一阶段 A/B 验证前，不要把滤波话题接入正式比赛任务。测试动作应原地、低速完成，周围留出安全空间并保持急停可用。

## 0. 同步、编译和单元测试

此阶段不需要启动机器狗或导航。

```bash
cd ~/comp2026_ws
git pull
catkin_make --pkg depthimage_to_laserscan allmovebase
source devel/setup.bash
catkin_make gravity_aligned_filter_test
./devel/lib/depthimage_to_laserscan/gravity_aligned_filter_test
```

通过标准：编译无错误，两个 gtest 均显示 `PASSED`。

## 1. 旁路 A/B 测试（不影响现有导航输入）

终端 A 按原方式启动导航。定位稳定后，在终端 B 启动实验滤波器：

```bash
cd ~/comp2026_ws
source devel/setup.bash
roslaunch allmovebase depth_ground_filter_experimental.launch
```

终端 C 启动并排统计：

```bash
cd ~/comp2026_ws
source devel/setup.bash
rosrun allmovebase scan_ab_monitor.py
```

终端 D 检查频率和诊断（分别运行）：

```bash
rostopic hz /scan_ground_filtered
rostopic echo /ground_filter/diagnostics
```

RViz 中同时添加两个 `LaserScan`：

- `/scan`：白色，原实现。
- `/scan_ground_filtered`：绿色，新实现。

依次保持每个状态约 5 秒：正常站立、低头扫地（pitch 约 12–15°）、恢复正常、左倾、右倾。不要在这一阶段移动位置。

第一阶段通过标准：

- `/scan_ground_filtered` 稳定在约 15 Hz，最低不应长期低于 10 Hz。
- 诊断通常为 `OK`；允许偶发 `WARN`（使用标称高度回退），但不应持续出现 IMU 超时或无姿态 `ERROR`。
- 正常站立时，绿色扫描与真实墙面/高于地面 6 cm 的障碍物位置一致。
- 低头扫地时，即使白色 `/scan` 出现约 1.0–1.3 m 的连续地面点，绿色扫描也不出现对应的连续地面弧线或整片近距离扫描。
- 恢复、左倾、右倾后，绿色扫描仍与环境结构一致，不产生残留地面点。

若绿色扫描整体向错误方向移动或真实墙面明显消失，停止测试，不进入第二阶段，保存监视器和诊断输出用于调整 `camera_mount_pitch_deg`、地面高度或阈值。

## 2. 接入 AMCL 和代价地图的闭环测试

必须先停止第一阶段导航，确认没有残留的 `amcl`、`move_base` 和相机节点，再重新启动。所有顶层任务 launch 都支持下面两个参数；以纯导航栈为例：

```bash
cd ~/comp2026_ws
source devel/setup.bash
roslaunch allmovebase stack_nav_base.launch \
  start_ground_filter_experimental:=true \
  navigation_scan_topic:=/scan_ground_filtered
```

如果平时使用顶层任务，可保持原命令，只追加相同参数。例如：

```bash
roslaunch allmovebase task_2026_navigation.launch \
  start_ground_filter_experimental:=true \
  navigation_scan_topic:=/scan_ground_filtered
```

确认实际订阅关系：

```bash
rostopic info /scan_ground_filtered
rostopic info /scan
```

`/scan_ground_filtered` 的订阅者应包含 `/amcl` 和 `/move_base`。`/amcl` 不应
订阅原始 `/scan`；`/move_base` 应继续订阅原始 `/scan`，但该输入只用于
Costmap clearing，不用于 marking。

实验闭环的 Costmap 输入职责为：

```text
/scan_ground_filtered -> marking=true,  clearing=false
/scan                 -> marking=false, clearing=true, inf_is_valid=false
```

定位稳定后记录基线：

```bash
rosrun tf tf_echo map odom
rostopic echo -n 1 /amcl_pose
```

原地低头扫地并恢复，等待 10 秒。为复现之前最敏感的静止更新场景，可在低头时运行 3–4 次：

```bash
rosservice call /request_nomotion_update
```

每次间隔约 1 秒，恢复后再记录 `map -> odom` 和 `/amcl_pose`。

第二阶段通过标准：

- 低头期间局部代价地图不出现由地面形成的扇形/整片障碍区；恢复后无需调用 `/move_base/clear_costmaps`。
- 静止更新前后 `map -> odom` 平移变化不超过 0.03 m、航向变化不超过 1°；AMCL 协方差不出现持续翻倍。
- 真实障碍物仍能进入局部代价地图，且机器人恢复正常姿态后环境墙面扫描保持稳定。
- 连续执行“正常—扫地—恢复”三轮，均满足以上条件。

## 回退

任一标准不满足时，停止当前 launch，按原命令启动即可；或者显式使用：

```bash
roslaunch allmovebase stack_nav_base.launch \
  start_ground_filter_experimental:=false \
  navigation_scan_topic:=/scan
```

默认值本身就是上述回退状态，原始 `/scan` 链路没有被删除或改写。

## 参数位置

滤波参数集中在 `src/allmovebase/config/gravity_ground_filter.yaml`。优先根据实测诊断调整：

- `camera_mount_pitch_deg`：相机静态俯角标定值。
- `nominal_camera_height`、`min_camera_height`、`max_camera_height`：相机到地面的高度范围。
- `ground_distance_threshold`：地面平面厚度容差。
- `min_obstacle_height`：保留障碍物的最低离地高度。
- `imu_timeout`：深度帧与 IMU 时间差上限。

不要在一次测试中同时修改多个参数；每次只改一项，并重复完整三轮姿态测试。

## 2026-08-15 实机回归记录

测试环境不是建图现场，因此本次结论用于验证地面滤波和相对稳定性，不替代地图现场的最终定位验收。

- 正常站立：滤波器约 15 Hz，地面高度约 0.412 m，诊断为 `OK`。
- 低头约 14.86°：原始 `/scan` 为 574/640 束，最近 0.994 m、中位数 1.043 m；滤波后仅保留 7/640 束远处环境点，最近 2.516 m。
- 局部代价地图：低头及 4 次 `/request_nomotion_update` 前后致命占用栅格均为 65，没有形成地面障碍区，也不需要调用 `/move_base/clear_costmaps`。
- `map -> odom`：平移变化约 3.16 cm，航向变化约 0.23°；恢复后连续观察保持不变。
- AMCL：协方差三项均下降，恢复后没有继续累积偏移。与原始扫描复现出的约 9.7 cm、4.9° 偏移相比明显改善。
- 真实障碍：相机前约 0.54 m 的障碍物能被 `/scan_ground_filtered` 稳定保留；移除后扫描立即回到环境墙面分布。
- 一次趴下异常已确认由手柄误触导致，不是 ROS 节点发令，不属于正式运行姿态范围。

结论：地面误检和局部代价地图污染问题通过；非建图现场的 AMCL 相对稳定性通过。由于平移结果比 3 cm 严格阈值高约 1.6 mm，仍需在地图现场按相同步骤做一次最终确认，不建议根据当前非地图环境继续调整 AMCL 或地面滤波参数。
