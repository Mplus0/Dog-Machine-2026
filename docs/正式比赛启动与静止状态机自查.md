# 正式比赛启动与静止状态机自查

本文档用于：

- 启动 2026 比赛正式全任务；
- 在机器狗保持静止的条件下检查 launch、导航前置条件和主控状态机分支；
- 单独测试识别阶段的身体抬头信号；
- 检查抬头后的导航姿态恢复。

当前正式全任务入口为：

```text
allmovebase/launch/task_2026_full.launch
```

正式状态机依次执行：运动主机准备、避障、四点 YOLO 巡检识别、异常区域抓取放置。

> **安全警告**
>
> 正式 launch 会主动发送起立、导航、识别姿态和机械臂任务。运行正式命令前必须清空机器狗及机械臂运动范围，确认急停可用，并确认 AMCL 初始位置和机械臂网络连接正确。

## 1. 终端初始化

以下命令假定机器狗上的工作空间为 `~/comp2026_ws`：

```bash
cd ~/comp2026_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash
```

每个新终端都至少需要执行：

```bash
source /opt/ros/noetic/setup.bash
source ~/comp2026_ws/devel/setup.bash
```

## 2. 正式比赛启动

只有避障、四点识别、机械臂抓取和放置均已单独通过后，才运行全任务：

```bash
cd ~/comp2026_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash

roslaunch allmovebase task_2026_full.launch \
  arm_command_required:=true \
  arm_require_transport_connected:=true
```

当前机械臂默认服务地址为 `192.168.31.56:47001`。地址不同时显式传入：

```bash
roslaunch allmovebase task_2026_full.launch \
  arm_command_required:=true \
  arm_require_transport_connected:=true \
  arm_server_host:=192.168.31.56 \
  arm_server_port:=47001
```

另开终端观察状态机报告：

```bash
source ~/comp2026_ws/devel/setup.bash
rostopic echo /full_task/report
```

另开终端观察最终结果：

```bash
source ~/comp2026_ws/devel/setup.bash
rostopic echo /full_task/succeeded
```

成功时最终结果为：

```text
data: true
```

## 3. 完全静态检查

本节不启动 ROS 节点，不会向机器狗发送运动指令。

### 3.1 Python 语法检查

```bash
cd ~/comp2026_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash

python3 -m py_compile \
  src/allmovebase/scripts/full_task.py \
  src/allmovebase/scripts/sequential_nav_inspect.py \
  src/message_transformer/scripts/lite3_motion_cmd.py
```

命令没有输出且退出码为 `0` 表示语法检查通过。

### 3.2 launch 结构检查

```bash
roslaunch-check "$(rospack find allmovebase)/launch/task_2026_full.launch"
```

列出正式 launch 可配置参数：

```bash
roslaunch --args allmovebase task_2026_full.launch
```

### 3.3 YOLO 结果解析逻辑检查

```bash
cd ~/comp2026_ws

python3 -c "import sys; sys.path.insert(0,'src/allmovebase/scripts'); from full_task import FullTask; cases=['rec_pose_1,A,normal','A,low','bad']; print([(x,FullTask._parse_detection_result(None,x)) for x in cases])"
```

预期结果：

```text
[
 ('rec_pose_1,A,normal', ('rec_pose_1', 'A', 'normal')),
 ('A,low', (None, 'A', 'low')),
 ('bad', (None, None, None))
]
```

### 3.4 识别位姿序列检查

```bash
python3 -c "import yaml; p='src/allmovebase/config/task_poses.yaml'; d=yaml.safe_load(open(p)); s=d['sequences']['recognition']; missing=[x for x in s if x not in d['goals']]; print('recognition=',s); print('missing=',missing); raise SystemExit(bool(missing))"
```

预期结果：

```text
recognition= ['rec_pose_1', 'rec_pose_2', 'rec_pose_4', 'rec_pose_3']
missing= []
```

## 4. 实机静止状态机自查

当前主控没有专门的 `dry_run` 参数。为了避免实机运动，必须同时关闭运动主机准备、三个任务阶段和机械臂桥接。

### 4.1 终端 A：启动 ROS Master

```bash
source /opt/ros/noetic/setup.bash
roscore
```

### 4.2 终端 B：持续发送零速度保护

保持此终端运行：

```bash
source ~/comp2026_ws/devel/setup.bash

rostopic pub -r 20 /cmd_vel geometry_msgs/Twist \
"{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"
```

### 4.3 终端 C：监听主控报告

必须在启动自查 launch 之前开始监听，因为 `/full_task/report` 不是锁存话题：

```bash
source ~/comp2026_ws/devel/setup.bash
rostopic echo /full_task/report
```

### 4.4 终端 D：以静止配置启动正式 launch 图

```bash
cd ~/comp2026_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash

roslaunch allmovebase task_2026_full.launch \
  prepare_motion_host:=false \
  run_obstacle:=false \
  run_inspection:=false \
  run_pick_place:=false \
  start_dog_arm_bridge:=false \
  start_arm_tcp_transport:=false \
  run_meter_audio:=false \
  camera_enable_color:=false
```

该配置仍会检查：

- 正式 launch 能否完整展开；
- 导航栈、地图、相机和 `/scan` 能否启动；
- `/move_base` Action Server 是否存在；
- `map -> base_link` TF 是否存在；
- `full_task` 能否完成初始化和成功结束状态转换。

该配置不会：

- 发布 `prepare_navigation`；
- 发布导航目标；
- 发送 `inspection_view_pose`；
- 触发 YOLO；
- 发送机械臂任务。

检查锁存结果：

```bash
rostopic echo -n 1 /full_task/succeeded
```

预期结果：

```text
data: true
```

## 5. 静止检查状态机失败分支

下面通过缩短总预算并提高避障阶段最低预算，使状态机在进入避障前主动拒绝执行。它会检查预算失败分支，但不会发布导航目标。

继续保持第 4.2 节的零速度保护，然后执行：

```bash
cd ~/comp2026_ws
source devel/setup.bash

roslaunch allmovebase task_2026_full.launch \
  prepare_motion_host:=false \
  run_obstacle:=true \
  run_inspection:=false \
  run_pick_place:=false \
  start_dog_arm_bridge:=false \
  task_budget_enable:=true \
  task_budget_total:=1.0 \
  min_obstacle_remaining:=999.0 \
  run_meter_audio:=false
```

预期日志包含：

```text
[task_budget] obstacle stage: budget low
full task finished: failed
```

检查结果：

```bash
rostopic echo -n 1 /full_task/succeeded
```

预期结果：

```text
data: false
```

自查过程中可提前在三个终端分别监听：

```bash
rostopic echo /move_base/goal
```

```bash
rostopic echo /lite3_motion_cmd
```

```bash
rostopic echo /dog_arm/task_cmd
```

以上三个话题在预算拒绝测试中都不应收到任务消息。

## 6. 单独测试识别阶段抬头信号

### 6.1 测试目标

验证以下完整链路：

```text
/lite3_motion_cmd
  -> lite3_motion_cmd.py
  -> /simple_cmd
  -> ros2qnx
  -> Lite3 运动主机
  -> 机器狗身体抬头
```

当前正式识别动作 `inspection_view_pose` 的实际流程为：

1. 连续发送零 `/cmd_vel` 约 1 秒；
2. 发送原地姿态模式 `0x21010D05`；
3. 发送身体俯仰轴 `0x21010130`；
4. 正式俯仰值为 `-6553`，负值表示抬头；
5. 俯仰指令重复发送 3 次，每次间隔 0.5 秒。

这不是独立云台动作，而是机器狗整体身体俯仰。测试时身体会实际运动。

### 6.2 测试前置条件

- 不得同时运行 `task_2026_full.launch`、`task_2026_navigation.launch` 或其他 `message_transformer.launch`；
- 机器狗四足稳定接触地面，周围没有人员和障碍物；
- 急停可用；
- 机器狗已经正常站立；
- `/lite3/robot_basic_state` 应为 `6` 或 `9`；
- 若状态为 `1`、状态缺失或持续跳变，不执行抬头测试。

### 6.3 终端 A：启动运动通信和语义动作节点

第一次建议先用较小幅度 `-3000` 验证动作方向：

```bash
cd ~/comp2026_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash

roslaunch message_transformer message_transformer.launch \
  inspection_pitch_value:=-3000 \
  navigation_pitch_value:=0
```

注意：该 launch 会占用运动主机 UDP 通信端口，不得与正式比赛 launch 同时启动。

### 6.4 终端 B：确认站立状态

```bash
source ~/comp2026_ws/devel/setup.bash
rostopic echo -n 1 /lite3/robot_basic_state
```

只在输出为以下任一状态时继续：

```text
data: 6
```

或：

```text
data: 9
```

### 6.5 终端 C：保持零速度

在整个抬头测试过程中保持运行：

```bash
source ~/comp2026_ws/devel/setup.bash

rostopic pub -r 20 /cmd_vel geometry_msgs/Twist \
"{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"
```

### 6.6 终端 D：监听下发到底层的指令

先启动监听，再发布抬头命令：

```bash
source ~/comp2026_ws/devel/setup.bash
rostopic echo /simple_cmd
```

### 6.7 终端 E：发布小幅度抬头动作

先确认动作节点已经订阅：

```bash
rostopic info /lite3_motion_cmd
```

应能看到 `/lite3_motion_cmd` 至少有一个订阅者。然后发布：

```bash
rostopic pub -1 /lite3_motion_cmd std_msgs/String \
"data: 'inspection_view_pose'"
```

软件链路正确时，`/simple_cmd` 应至少出现：

```text
cmd_code: 553716997
cmd_value: 0
```

它对应原地姿态模式 `0x21010D05`。

随后俯仰指令应重复出现 3 次：

```text
cmd_code: 553713968
cmd_value: -3000
```

它对应俯仰轴 `0x21010130`。

判定标准：

- `/lite3_motion_cmd` 有订阅者；
- `/simple_cmd` 出现原地模式指令；
- `/simple_cmd` 出现 3 次 `cmd_value: -3000`；
- 机器狗保持原地，身体产生小幅度抬头；
- 没有前进、后退或失稳。

`/simple_cmd` 只能证明软件已经向通信桥发送命令；最终是否执行必须结合实机动作和运动主机状态判断。

### 6.8 恢复导航姿态

确认小幅度抬头后立即执行恢复：

```bash
rostopic pub -1 /lite3_motion_cmd std_msgs/String \
"data: 'navigation_view_pose'"
```

预期现象：

- 俯仰轴值 `0` 重复发送 3 次；
- 身体恢复正常俯仰；
- 节点切回自主移动控制模式；
- 因 `/cmd_vel` 持续为零，机器狗仍保持静止。

### 6.9 测试正式比赛抬头值

小幅度测试通过后，停止第 6.3 节的 launch，重新以正式值启动：

```bash
roslaunch message_transformer message_transformer.launch \
  inspection_pitch_value:=-6553 \
  navigation_pitch_value:=0
```

保持零速度发布器和 `/simple_cmd` 监听器运行，再次执行：

```bash
rostopic pub -1 /lite3_motion_cmd std_msgs/String \
"data: 'inspection_view_pose'"
```

此时 `/simple_cmd` 应出现 3 次：

```text
cmd_code: 553713968
cmd_value: -6553
```

机器狗应保持原地并达到正式识别使用的抬头姿态。验证完成后恢复：

```bash
rostopic pub -1 /lite3_motion_cmd std_msgs/String \
"data: 'navigation_view_pose'"
```

### 6.10 异常处理

如果机器狗出现前后移动趋势，立即持续发送零速度：

```bash
rostopic pub -r 20 /cmd_vel geometry_msgs/Twist \
"{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"
```

如果仍无法停止，使用软急停：

```bash
rostopic pub -1 /lite3_motion_cmd std_msgs/String \
"data: 'estop'"
```

软急停可能需要按 Lite3 实机规程重新解除和恢复，仅在异常运动时使用。

出现以下任一情况时判定测试失败，并停止后续正式值测试：

- 没有 `/simple_cmd` 输出；
- 没有原地模式指令；
- 俯仰值方向错误；
- 机器狗发生前后移动；
- `robot_basic_state` 丢失或进入异常状态；
- 抬头后无法通过 `navigation_view_pose` 恢复。

## 7. 自查结束与正式运行切换

结束自查时依次执行：

1. 发布一次 `navigation_view_pose`，确认身体俯仰恢复；
2. `Ctrl+C` 停止抬头测试 launch；
3. 保持零速度发布器到测试 launch 完全退出；
4. `Ctrl+C` 停止零速度发布器；
5. 停止单独启动的 `roscore`；
6. 确认没有残留的 `message_transformer`、`move_base` 或任务节点；
7. 再启动正式比赛 launch。

检查残留节点：

```bash
rosnode list
```

检查残留速度发布者：

```bash
rostopic info /cmd_vel
```

> **重要：**正式任务开始前必须停止测试用的持续零速度发布器，否则它会与 `move_base` 的速度命令冲突，导致机器狗无法正常导航。

## 8. 当前自查覆盖范围

上述流程可覆盖：

- Python 和 launch 基础合法性；
- 识别结果文本解析；
- 识别点配置完整性；
- 导航栈、地图、LaserScan 和 TF 前置条件；
- 主状态机空任务成功分支；
- 主状态机预算拒绝失败分支；
- `inspection_view_pose` 抬头语义命令链路；
- 正式抬头值 `-6553`；
- `navigation_view_pose` 姿态恢复。

当前仓库没有模拟 `move_base`、YOLO 和机械臂的完整 dry-run 测试框架，因此在机器狗绝对静止的前提下，无法覆盖“导航成功 -> 四点识别成功 -> 抓取成功 -> 放置成功”的完整成功路径。
