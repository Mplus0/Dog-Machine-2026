# 项目验收现场快速调试清单

## 1. 目标和原则

本文档只排查“现场变化”对项目的影响，建议总用时控制在 **30–45 分钟**。

不重复以下已验证内容：

- 重力对齐地面滤波单测和低头/左右倾斜测试。
- `/scan_ground_filtered` 标记障碍、`/scan_ground_clearing` 清除障碍。
- AMCL 围挡 v2 地图在已测场地的 C 组定位稳定性。
- Gate7 启停回归、避障和已调整的代价地图参数。
- 已通过的分阶段导航回归。

现场仅在发现差异时修改参数。每修改一项立即记录，不同时调多个参数。

### 现场最短执行路径

1. [ ] 记录两端 IP，ping 互通，密钥哈希一致。
2. [ ] 启动导航空环境，小幅移动后 AMCL 稳定，主要围挡/箱子与地图对齐。
3. [ ] 只实测 `pickup_pose`、`place_pose_A/D` 和现场变动过的点。
4. [ ] 确认机械臂目标坐标稳定；仅在放置位变化时运行 `calibrate_place_pose`。
5. [ ] TCP `transport_connected=true`，手动执行一次 `pick` 和一次 `place_to_zone`。
6. [ ] 停止手工调试节点，最终全流程只运行一次。

某项通过后直接进入下一项，不重复其旧验收。某项失败时再查看本文档对应章节。

## 3. 第一步：物理和 IP 检查（5 分钟）

### 3.1 物理检查

- 机器狗相机高度、俯仰角和固定件与测试时一致。
- 机械臂、夹爪和眼在手上相机没有松动。
- 围挡开口、三个箱子和起点方向与地图定义基本一致。
- 先清空机器狗和机械臂的运动范围，再通电。

### 3.2 获取 IP

机器狗端：

```bash
hostname -I
ip -4 addr
```

机械臂端：

```bash
hostname -I
ip -4 addr show wlan0
```

当前默认值为：

- 机器狗：`192.168.31.192`
- 机械臂：`192.168.31.56`
- TCP 端口：`47001`

如 IP 变化，不需要立即修代码，后面通过 launch 参数传入新 IP。

两端互相执行：

```bash
ping -c 3 <对端IP>
```

比较两端密钥文件的哈希，输出必须完全相同：

```bash
sha256sum ~/.ros/dog_arm_shared_secret
```

不要打印或复制密钥原文。

**通过标准：** 两端在同一网段、互相 ping 通、密钥哈希一致。

## 4. 第二步：地图、现场障碍和 AMCL（5–8 分钟）

当前默认 AMCL 地图为：

```text
~/comp2026_ws/src/allmovebase/map/map_amcl.yaml
  -> arena_amcl_fence_v2.pgm
```

导航静态地图为：

```text
~/comp2026_ws/src/allmovebase/map/map.yaml
  -> arena_nav_manual_3.pgm
```

两张地图用途不同，不要只修改其中一张就认为现场已同步。

### 4.1 启动导航环境

```bash
cd ~/comp2026_ws
source devel/setup.bash
roslaunch allmovebase task_2026_obstacle_test.launch run_obstacle_task:=false
```

在 RViz 只看以下内容：

- `/amcl_map`
- `/scan_ground_filtered`
- Global Costmap
- Local Costmap
- RobotModel/TF

在起点使用 `2D Pose Estimate`，然后让机器狗做一次小角度转动或短距离移动，等 AMCL 收敛。不要仅静止等待。

### 4.2 只判断现场差异

- 围挡和固定箱子的扫描应与 `/amcl_map` 大体重合。
- 少量外围杂物扫描可不理会；若其导致位姿持续跳跃，先遮挡/移除杂物。
- 临时障碍物不写入 PGM，由动态代价地图处理。
- 可移动箱子与地图不一致时，现场最快方案是把箱子移到地图对应位置。
- 如围挡结构、开口或固定障碍无法调整，必须重做地图；不要用反复设置 AMCL 初始位姿来掩盖地图几何错误。

若必须更新地图，保留原图，新建 `map_*_site.yaml/pgm`，用 launch 参数切换，不要现场覆盖原始 v2 地图。

**通过标准：** 小幅移动后位姿稳定，围挡/主要固定箱子扫描与地图无持续系统性偏移。

## 5. 第三步：导航坐标现场快速实测（8–12 分钟）

任务点统一位于：

```text
~/comp2026_ws/src/allmovebase/config/task_poses.yaml
```

时间不足时不重跑全部旧回归，优先检查：

1. `pickup_pose`：机械臂能看到并够到抓取物。
2. `place_pose_A` 和 `place_pose_D`：放置区两端极限点。
3. 现场位置变化的 `rec_pose_*`。
4. 围挡/避障区变化时再检查 `obs_start` 和 `obs_end`。

可先用 RViz `2D Nav Goal` 逐点发送。机器狗到达后，如需记录当前实测位姿：

```bash
rostopic echo -n 1 /amcl_pose
```

将 `pose.pose.position` 的 x/y/z 和 `pose.pose.orientation` 的 x/y/z/w 写回对应任务点。修改 YAML 后需重启任务节点，因为坐标只在启动时读取。

现场判断以“任务能执行”为主：

- 机器狗未碰围挡/箱子，且不在终点反复小幅调整。
- 识别点相机视野覆盖目标。
- 抓取/放置点的车体朝向正确，机械臂工作空间足够。
- 如终点落在膨胀区内，优先把目标点向空旷侧平移约 `0.10 m`，不要第一时间改全局膨胀参数。

## 6. 第四步：机械臂抓取和放置（8–12 分钟）

### 6.1 启动机械臂比赛节点

```bash
cd /home/sunrise/dog/ros2_red_block_ws
source install/setup.bash
ros2 launch red_block_grasp_mplus0 competition_arm_task.launch.py \
  show_window:=false \
  tcp_bind_host:=<机械臂IP> \
  tcp_allowed_client_ip:=<机器狗IP>
```

确认以下节点存在：

```bash
ros2 node list | grep -E 'dog_arm_tcp_server|roarm_driver|target_localizer|visual_servo|competition_arm'
```

### 6.2 抓取快速检查

抓取点不是固定 XYZ；它由相机识别、深度、手眼标定和 `grasp_offset_*` 共同决定。现场只检查安装、光照和物料变化：

```bash
ros2 topic hz /red_block/target_base
ros2 topic echo --once /red_block/target_base
ros2 param get /visual_servo_task_node grasp_offset_x_mm
ros2 param get /visual_servo_task_node grasp_offset_y_mm
ros2 param get /visual_servo_task_node grasp_offset_z_mm
```

只在“每次都向同一方向偏”时修正 `grasp_offset_*`。如目标坐标抖动或跳变，先修光照、遮挡和相机安装，不要用 offset 掩盖。

### 6.3 固定放置坐标

放置点位于：

```text
/home/sunrise/dog/ros2_red_block_ws/src/red_block_grasp_mplus0/config/place_pose.yaml
```

默认为 `X=260, Y=180, Z=120 mm`。如现场机械臂安装位置或放置容器位置变化，停止比赛 launch，仅启动驱动和只读标定工具。

终端 1：

```bash
ros2 run red_block_grasp_mplus0 roarm_driver_node --ros-args -p port:=/dev/ttyUSB0
```

终端 2：

```bash
cd /home/sunrise/dog/ros2_red_block_ws
source install/setup.bash
ros2 run red_block_grasp_mplus0 calibrate_place_pose
```

用已验证的网页/手动方式移动机械臂，脚本中输入：

```text
status
capture
show
save
SAVE
```

保存后重新构建并重启比赛 launch：

```bash
cd /home/sunrise/dog/ros2_red_block_ws
colcon build --packages-select red_block_grasp_mplus0
source install/setup.bash
```

**通过标准：** 目标坐标稳定；一次抓取能闭爪、抬升并保持；一次放置能到固定点、开爪并回初始位。

## 7. 第五步：机器狗—机械臂 TCP 闭环（5 分钟）

先保持机械臂 `competition_arm_task.launch.py` 运行。

机器狗端单独启动通信：

```bash
cd ~/comp2026_ws
source devel/setup.bash
roslaunch dog_arm_bridge dog_arm_bridge.launch arm_server_host:=<机械臂IP>
```

新开机器狗终端：

```bash
rostopic echo -n 1 /dog_arm/transport_connected
rostopic echo -n 1 /dog_arm/transport_status
```

`transport_connected.data` 必须为 `true`。如为 `false`，只排查：

1. 机械臂 IP 和狗端 `arm_server_host`。
2. 机械臂 `tcp_bind_host` 和 `tcp_allowed_client_ip`。
3. 两端 `47001` 端口。
4. 共享密钥哈希。
5. Wi-Fi 客户端隔离/防火墙。

通信连接本身不会驱动机械臂。当机器狗已在抓取点、人员和环境安全后，只执行一次完整双向测试：

```bash
rosrun dog_arm_bridge dog_arm_task_cli.py pick \
  --task-id onsite_pick_001 --timeout 180
```

确认返回 `pick_success`，再让机器狗到放置位置，执行：

```bash
rosrun dog_arm_bridge dog_arm_task_cli.py place_to_zone \
  --task-id onsite_place_001 --timeout 60
```

确认返回 `place_success`。这一次已同时验证：

- 狗端发送 TCP。
- 机械臂接收并执行。
- 机械臂返回 TCP 结果。
- 狗端按 `task_id` 匹配结果。
- 抓取后保持夹爰，放置指令到达后再开爪。

手工通信测试结束后，**停止单独启动的 `dog_arm_bridge.launch`**，避免最终 launch 重复启动 TCP 客户端。

## 9. 快速停止与现场决策

出现下列任一情况，立即用手柄/急停停止动作，再 `Ctrl-C` 退出 launch：

- 机器狗实际位置与 RViz 持续系统性偏移。
- 机械臂抓取/放置趋势明显朝错误方向。
- TCP 断线时机械臂仍在执行旧任务。
- 局部/全局代价地图将明显障碍物当作可通行区。

如仅有动态代价地图残留，可在障碍物已移除后执行：

```bash
rosservice call /move_base/clear_costmaps "{}"
```

现场时间不足时，按以下优先级决策：

1. **安全和定位不对：** 停止，不继续全流程。
2. **只有个别导航点不合适：** 只改 `task_poses.yaml` 对应点。
3. **只有固定放置点不合适：** 只运行 `calibrate_place_pose`。
4. **抓取坐标稳定但有固定偏差：** 小幅修正 `grasp_offset_*`。
5. **通信不通：** 只查 IP、端口、密钥和 Wi-Fi 隔离，不调状态机。

## 10. 最终放行标准

以下条件同时满足即可进入项目验收：

- [ ] 两端网络稳定，TCP `transport_connected=true`。
- [ ] AMCL 经小幅移动后收敛，无持续坐标/角度跳跃。
- [ ] 围挡和主要固定障碍扫描与地图基本一致。
- [ ] 抓取点、放置区两端和变化过的识别点可到达。
- [ ] 一次 `pick` 返回 `pick_success`，物料在移动期间保持夹紧。
- [ ] 一次 `place_to_zone` 返回 `place_success`，物料成功释放。
- [ ] 最终 `task_2026_full.launch` 完整执行一次，无需人工清除代价地图或重置状态机。
