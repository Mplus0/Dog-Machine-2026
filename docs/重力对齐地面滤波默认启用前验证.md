# 重力对齐地面滤波：默认启用前分阶段验证

## 1. 目的与最终决策

本文用于判断是否可以把以下实验参数改为导航任务的默认值：

```text
start_ground_filter_experimental:=true
navigation_scan_topic:=/scan_ground_filtered
```

本文只用于验收，不要求在验收期间修改滤波、AMCL、Costmap、TF 或 launch 参数。任一硬性项目失败时应停止后续阶段，保存结果，再根据证据修改代码或配置。

最终有三种结论：

- `GO-OBSTACLE`：允许先在 `task_2026_obstacle_test.launch` 中默认启用。
- `GO-ALL`：允许在 navigation、pick-place、full task 中逐步默认启用。
- `NO-GO`：保持当前显式参数启用方式，不修改默认值。

不要一步将 `stack_nav_base.launch` 改为全局默认。应先通过 `GO-OBSTACLE`，再完成全任务回归，最后考虑 `GO-ALL`。

## 3. 安全要求

开始任何阶段前必须满足：

- 测试区域平整，机器人周围至少留出 1 m 空间。
- 手柄放在不易误触的位置，急停或人工接管可立即使用。
- 除明确的行走阶段外，不发送导航目标和 `/cmd_vel`。
- 姿态测试只包含正常站立、低头、恢复、左倾和右倾，不测试趴下。
- 每次只改变一个条件，动作完成后至少保持 5 秒。

出现以下任一情况立即停止当前 launch：

- 非预期趴下、行走、转向或持续非零 `/cmd_vel`。
- `/ground_filter/diagnostics` 持续为 `ERROR`。
- `/scan_ground_filtered` 长期低于 10 Hz。
- RViz 中出现整片地面障碍、坐标突然跳变或 TF 大面积丢失。
- 真实障碍物没有被扫描或 Costmap 标记。

停止命令为启动终端中的 `Ctrl+C`。不要使用 `kill -9`；只有记录失败证据后，才可按需调用：

```bash
rosservice call /move_base/clear_costmaps
```
